# آماده‌سازی امضای نسخه Release اندروید

## کلید پایدار پروژه
یک keystore پایدار با نام فایل `rescueguide-release.jks` و alias برابر `rescueguide-release` تهیه شده است. فایل اصلی و نسخه Base64 آن در بسته خصوصی `RescueGuide-Release-Keys.zip` تحویل صاحب پروژه می‌شود. این ZIP را در مخزن عمومی GitHub یا ZIP سورس قرار ندهید.

## چرا امضای پایدار لازم است؟
نسخه‌ای که برای انتشار یا به‌روزرسانی ارائه می‌شود باید با کلید امضای ثابت امضا شود. اگر کلید از دست برود یا در نسخه بعدی عوض شود، کاربران ممکن است نتوانند برنامه را روی نسخه قبلی به‌روزرسانی کنند. بنابراین از دست دادن فایل keystore یا رمزهای آن می‌تواند انتشار به‌روزرسانی را مختل کند.

## قواعد امنیتی
- فایل keystore و رمزهای آن را در مخزن عمومی، ZIP سورس، Issue یا APK قرار ندهید.
- فایل JKS را حداقل در دو محل امن و مستقل پشتیبان‌گیری کنید.
- رمزهای keystore و key را در یک محل جداگانه و امن نگهداری کنید.
- هرگز برای ساخت‌های بعدی یک کلید تازه و متفاوت نسازید.
- کلید امضای اندروید با RSA Public Key پرداخت کافه‌بازار متفاوت است.

## Secrets موردنیاز برای GitHub Actions
در مخزن GitHub به مسیر زیر بروید:

Settings → Secrets and variables → Actions → New repository secret

چهار Secret زیر را با همین نام‌ها اضافه کنید:
- `ANDROID_KEYSTORE_BASE64`: تمام متن فایل `ANDROID_KEYSTORE_BASE64.txt` داخل بسته کلید.
- `ANDROID_KEYSTORE_PASSWORD`: رمز keystore که جداگانه به صاحب پروژه تحویل داده شده است.
- `ANDROID_KEY_ALIAS`: مقدار ثابت `rescueguide-release`.
- `ANDROID_KEY_PASSWORD`: رمز کلید که جداگانه به صاحب پروژه تحویل داده شده است.

این مقادیر را فقط در بخش Secrets خصوصی مخزن وارد کنید؛ هرگز در فایل‌های پروژه یا چت عمومی قرار ندهید. ابزار فعلی اتصال GitHub امکان نوشتن Repository Secrets را ندارد، بنابراین این چهار مقدار باید توسط صاحب مخزن در تنظیمات GitHub ثبت شوند.

## ساخت Release
پس از ثبت هر چهار Secret، اجرای workflow با نام `RescueGuide Android CI` در GitHub Actions، علاوه بر Debug، یک APK امضاشده Release می‌سازد. اگر Secretها کامل نباشند، مرحله Release عمداً اجرا نمی‌شود و فقط Debug تولید خواهد شد. خروجی Release باید با موفقیت از مرحله بررسی امضا عبور کند.

## وضعیت و محدودیت
تهیه کلید به‌تنهایی به معنی ساخته‌شدن APK Release نیست. تا زمانی که Secretها در GitHub ثبت و workflow سبز نشده، هیچ APK را نسخه Release امضاشده تلقی نکنید. نصب روی گوشی واقعی و آزمایش رفتار برنامه نیز باید جداگانه انجام شود.
