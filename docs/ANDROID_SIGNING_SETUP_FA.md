# آماده‌سازی امضای نسخه Release اندروید

## چرا امضای پایدار لازم است؟
نسخه‌ای که برای انتشار یا به‌روزرسانی ارائه می‌شود باید با کلید امضای ثابت امضا شود. اگر کلید از دست برود یا در نسخه بعدی عوض شود، کاربران ممکن است نتوانند برنامه را روی نسخه قبلی به‌روزرسانی کنند. بنابراین از دست دادن فایل keystore یا رمزهای آن می‌تواند انتشار به‌روزرسانی را مختل کند.

## قواعد امنیتی
- فایل keystore و رمزهای آن را در مخزن عمومی، فایل ZIP سورس، Issue، پیام عمومی یا APK قرار ندهید.
- کلید خصوصی را در چت ارسال نکنید.
- فایل keystore را حداقل در دو محل امن و مستقل پشتیبان‌گیری کنید.
- مقادیر امضای Release باید به‌صورت GitHub Actions Secrets ذخیره شوند.
- هرگز برای ساخت‌های بعدی یک کلید تازه و متفاوت نسازید.

## Secrets موردنیاز برای CI
پس از تهیه یک keystore پایدار، در مخزن GitHub به مسیر زیر بروید:

Settings → Secrets and variables → Actions → New repository secret

نام‌های زیر برای تنظیمات CI در نظر گرفته شده‌اند:
- `ANDROID_KEYSTORE_BASE64`: محتوای فایل keystore به‌صورت Base64.
- `ANDROID_KEYSTORE_PASSWORD`: رمز keystore.
- `ANDROID_KEY_ALIAS`: نام alias کلید.
- `ANDROID_KEY_PASSWORD`: رمز کلید.

این Secrets را فقط در تنظیمات خصوصی مخزن ثبت کنید. آن‌ها را در فایل‌های پروژه یا پیام‌ها ننویسید.

## وضعیت فعلی
در حال حاضر هیچ keystore پایدار متعلق به صاحب برنامه به مخزن متصل نشده و هیچ APK امضاشده Release ساخته نشده است. تا زمان تهیه و ثبت امن این موارد، خروجی CI فقط باید Debug تلقی شود؛ نباید APK بدون امضا یا Debug به‌عنوان نسخه Release معرفی شود.

## مرحله بعد
پس از آماده‌شدن اطلاعات محصول بازار و انتخاب/تهیه کلید امضای پایدار، پیکربندی CI برای ساخت Release امضاشده تکمیل می‌شود. فایل keystore و رمزهای آن را در اختیار افراد دیگر قرار ندهید.
